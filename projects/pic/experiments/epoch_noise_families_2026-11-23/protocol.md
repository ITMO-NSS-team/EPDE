# Full-record discovery under measurement noise

Run the 15 core systems and the harmonic oscillator with paired seeds 923701–923703. Compare three new 5% conditions to the original full-record campaign's clean and 5% iid Gaussian controls. Inject errors independently across fields before window selection, frequency estimation, finite differences, and discovery. Every comparison uses the entire original grid. The fixed budget is 50 epochs for scalar systems and 150 for coupled systems.

For each field, set the noise scale to 0.05 times its population standard deviation. Constant fields receive zero perturbation. Sparse spikes occupy 1% of positions sampled uniformly without replacement, rounded to the nearest integer with a minimum of one. Their signs are independent and their magnitude fixes the field-wide RMS at the target. Correlated Gaussian errors use stationary separable AR(1) filters with lag-one correlation 0.8 per grid step along every axis. Signal-dependent Gaussian errors have local standard deviation equal to the target times the absolute field value divided by the field RMS. The Gaussian models match in expected mean-square error. The per-run table records each realized RMS.

Use the native NSGA-II first front at the last epoch for the primary complete-system recovery endpoint. Count each run once when it returns the catalog structure or a verified equivalent system, including Lorenz identities that span all three laws. Check generation anywhere in the archive and the ordinary, two-slab, and multiscale archive fronts. Report the oscillator control separately and show the Lorenz identity audit alongside the recovery totals. Pair each gain or loss within dataset and search seed. One random measurement realization per seed means the design measures the joint variation from measurements and search.

Run `python campaign.py` from this folder to start or resume. A receipt covers each verified new archive and score file. The campaign checks completed receipts on restart and regenerates measurements to verify all field hashes during scoring. It runs the first oscillator seed under all three families, then schedules scalar work on one lane until baseline discovery finishes. At full capacity it runs four regular workers and one Navier–Stokes worker, after any pending full-budget baseline Navier–Stokes replay.

Following the mid-campaign CPU check, the remaining workers shared one OS affinity mask covering six of this machine's eight logical CPUs. Search math libraries use one thread each. The workers use below-normal scheduling priority on Windows so interactive workloads take precedence. New searches wait until a three-second sample of host utilization is at most 62.5%, leaving room for the next single-threaded worker. `python cpu_budget.py --apply` applies the same limits to both experiment pipelines if they are already running. Child processes inherit the mask.

The live [findings](findings.md) and [per-run table](runs.csv) update as searches finish. The final table has 960 rows covering 240 dataset–seed–condition combinations and four fronts. The [Lorenz table](historical_lorenz.csv) has 30 rows for native and multiscale identity credit. Run `python test_measurements.py` to check the generators independently.
