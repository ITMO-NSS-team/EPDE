# EPDE: результаты экспериментов и как их воспроизвести

Состояние на 12 ноября 2026 г. (ветка `domain_refactor`).

Документ собирает выводы из запусков EPDE. Часть выводов опирается на офлайн-анализ, код для него не прилагается.
Для старых запусков указан только коммит EPDE, на котором они шли. Код запуска (раздел 8) дан для текущей версии:
коммит `9bd360e` плюс правило инвариантов (патч `invariant_terms_on_9bd360e.patch` в этой папке).

Содержание:

## 1. Главное

- **Универсальный поиск U** (плоский режим + NSGA-II; с коммита `48e3789` это поведение EPDE по умолчанию) на 13
  тестовых системах (чистые данные и 5 % шума, 3 сида, слабая форма, 78 прогонов):
  - точный закон хотя бы раз сгенерирован в 72 прогонах из 78;
  - на финальном первом фронте он удержан строго в 53 прогонах, с учётом допустимых форм (раздел 3) — в 68;
  - случаев «закон был найден, но потерян поиском» нет. Из 10 промахов в 8 истина хуже другой формулы на данных
    этого прогона (окно слабой формы, шум), ещё в 2 закон ни разу не был сгенерирован.
- **Слабая форма: главный источник ошибок — выбор окна.** Шлюз «половины мощности» (окно допустимо, только если
  сохраняет не меньше половины дисперсии каждого поля) стал умолчанием в `9bd360e`. На 9 ячейках батареи, где он
  сдвигает окно, он ничего не ухудшил и одну ячейку улучшил.
- **Роботы, вращение.** 90–97 % первого фронта занимают переписывания закона через тождество единичной окружности
  c² + s² = 1. Два способа это убрать, оба поднимают восстановление:
  - правило инвариантов: в сильной форме переменных восстановлено 10 из 12 вместо 8, в слабой — 11 из 12 вместо 2;
  - поиск по одной переменной, где вторая компонента подаётся как токен данных: 12 из 12 и 10 из 12.
- **Роботы, дрейф.** Сильная форма восстанавливает 4 системы из 7, слабая — 0 из 7: в слабых строках токены
  памяти становятся копиями цели.
- **Роботы, поля.** При свободном выборе левой части у плотности rho никогда нет цели по времени. Фиксация цели
  по оси времени (`target_axes=0`) возвращает закон переноса: сейчас в 3 записях из 4 обсчитанных, без неё — в 0.
  С новыми токенами потока Q и V (раздел 7) закон находится с меньшей невязкой, но тоже только с `target_axes=0`.

## 2. Метод: универсальный поиск U

U — это плоский режим правой части (`system_rps_mode='plain'`) с движком NSGA-II (`engine='nsga2'`). С `48e3789`
EPDE включает U сам, если выбраны plain + nsga2. Состав:

- одна подгонка (WLS) на кандидата; цель (левая часть) — отдельный ген;
- константа не оптимизируется: проверяются обе версии, S и S+{1}; если ни одна не доминирует, в популяцию идут обе;
- заполнение и обрезка уравнения (`fill_prune`), правило произведения (`product_rule`), ходы по множителям;
- нишевание по переменным (`niching='auto'` → `'per_variable'` для систем из нескольких уравнений);
- ранняя остановка `'auto'`.

Целевые функции — две на каждое уравнение: WAPE (невязка) и нестабильность `dyad` (по каждой оси). По переменным
они не усредняются.

Настройки всех запусков в этом документе:

| Настройка | Значение |
|---|---|
| движок / режим | `engine='nsga2'`, `system_rps_mode='plain'` |
| метрики | `discrepancy_metric='wape'`, `instability_metric='dyad'` |
| производные | FD, `accuracy=4` (у систем роботов свои схемы, раздел 6) |
| граница, популяция | `'auto'` (createDomain без `boundary_width`, популяция по умолчанию); у дрейфа граница задана историей токенов памяти |
| членов в уравнении | `equation_terms_max_number=7` (6 членов + цель); дрейф роботов — 9 |
| множителей в члене | 1–2 (0.65 / 0.35); роботы-1D: 1–3 (0.5 / 0.35 / 0.15) |
| степени | `data_fun_pow=3`, `deriv_fun_pow=2` |
| дополнительные токены | сетка (степень ≤ 2), тригонометрия с частотой из данных, у роботов — свои семейства |
| эпохи | батарея: 50 (одно уравнение), 150 (lv, Lorenz, NS); роботы: 20 (spin, drift), 30 (поля) |
| сиды | `np.random` и `random` = сид прогона, `system_rps_params={'variable_order_seed': сид}` |

Минимальный вызов EPDE с теми же настройками (для своих данных; сами запуски шли через обвязку из раздела 8):

```python
from epde.interface.interface import EpdeSearch
from epde.interface.prepared_tokens import GridTokens, TrigonometricTokens

search = EpdeSearch(use_solver=False, multiobjective_mode=True, system_rps_mode='plain', engine='nsga2',
                    discrepancy_metric='wape', instability_metric='dyad', device='cpu',
                    evaluation_form='weak',                       # или 'strong' (по умолчанию)
                    system_rps_params={'variable_order_seed': 0})  # + 'target_axes': 0, 'invariant_terms': 'refuse'
_, domain = search.createDomain((t,), ID=0)                       # граница 'auto'
search.set_preprocessor(default_preprocessor_type='FD', preprocessor_kwargs={'accuracy': 4})
_, trajectory = search.createTrajectory({'u': u}, domain, cache_id=0)
search.fit(data=[trajectory], max_deriv_order=(2,), data_fun_pow=3, deriv_fun_pow=2,
           equation_terms_max_number=7, equation_factors_max_number={'factors_num': [1, 2], 'probas': [0.65, 0.35]},
           additional_tokens=[TrigonometricTokens(freq_from_data=2, dimensionality=0),
                              GridTokens(labels=['t'], max_power=2, dimensionality=0)])
```

## 3. Как засчитывается результат

- Смотрится **финальный первый фронт (L0)**. Переменная «удержана», если на L0 есть уравнение этой переменной,
  совпадающее по набору членов (цель + члены; константа не учитывается) с одной из перечисленных форм.
- Формы истины для батареи — словарь `TRUTH` в `run_auto.py`, для роботов — `truth()` в `robot_systems.py`.
- **Строго** — только сам закон. **С учётом допустимых форм** (основной счёт) засчитываются ещё:
  - тождества (например, у Лоренца сумма законов, у вращения `c·c' = −s·s'`);
  - для давления в NS — уравнение Пуассона;
  - усечение: закон плюс ведущие члены ошибки разностной схемы (на чистых heat_solar и pde_divide коэффициенты
    этих членов совпали с теоретическими: q = 1.00).
- FULL — система, в которой засчитано каждое уравнение. Для частичного успеха считаются PARTIAL (истинное
  подмножество) и SUPERSET (истина плюс лишние члены), а также TPR = TP / (TP + FN + FP) — мера Жаккара по
  наборам членов, как в WSINDy.
- **Для роботов истины нет.** Опорные формы — это законы, найденные раньше на тех же данных отдельным
  best-subset-конвейером. Например, для вращения `dc/dt = −ω s`; для полей — перенос, затухание с вращением,
  хиральная форма.

## 4. Батарея из 13 тестовых систем (7–8 ноября; коммит `48e3789`)

**Системы.**
- Одно уравнение: ode, vdp, wave, heat_solar, burgers, kdv, ks, ac, pde_compound, pde_divide.
- Системы: lv, lorenz, ns.

Данные: `projects/pic/data`. Шум — 5 % от std каждого поля, генератор `[seed, номер системы]`. Слабая форма,
сиды 0–2, чистые данные и 5 % шума: всего 78 прогонов.

Тогда U работал как набор «рук» в обвязке поверх EPDE. Позже его встроили в EPDE (`48e3789`) и проверили на
8 ячейках (burgers, kdv, lv ×3, lorenz, ns): потоки вычислений побитово совпали.

**Итог:**

| | Прогонов |
|---|---|
| точный закон сгенерирован хотя бы раз | 72 / 78 |
| удержан строго | 53 |
| удержан + тождества | 59 |
| удержан с любым зачётом (+ усечение, + Пуассон) | 68 |
| потерян поиском после того, как был найден | 0 |

**Почему не засчитаны 10 прогонов.**

Истина хуже другой формулы на данных этого прогона (8):
- wave 5 %, все 3 сида: `u_xx = a·u + c` — артефакт окна слабой формы. При выбранном окне u_tt в 25 раз меньше
  u_xx, и шум в нём доминирует;
- ac 5 %, сиды 1 и 2;
- vdp 5 %, ode 5 %, lv 5 % (по одному сиду): подгонки шума формами с тригонометрией и временем.

Закон ни разу не сгенерирован (2):
- pde_compound 5 %, сид 0: окно даёт всего 4 строки по времени;
- ns чистые, сид 1: уравнения импульса для u и p не появились за 150 эпох.

**Сравнение с прежними вариантами.**
- burgers, kdv, lv, lorenz чистые — так же.
- lorenz 5 % и ns 5 % — лучше.
- ns чистые — хуже: строго 1 из 3 против 3 из 3. Вероятная причина — заполнение (fill); не проверено.

**Фронты по отдельным уравнениям против общего архива системы.** Произведение фронтов по переменным
сохраняет зачёт первого уровня в 17 из 18 связанных прогонов. Теряет на ns: уравнение неразрывности занимает оба
слота, u и v. Вывод: общий архив системы оставлен.

**Офлайн-наблюдения (кода нет).** Чистые heat_solar и pde_divide проигрывают модифицированному уравнению
решателя, которым генерировались данные. На pde_divide лишние члены на L0 в точности равны −h²/6 и h²/12 для
центральной схемы 2-го порядка. Поэтому введён зачёт за «усечение».

### 6.4 Ревизия 12 ноября (коммит `9bd360e`; правило инвариантов — `9bd360e` + патч)

Руки: U2 — сильная форма, UW2 — слабая (обе — умолчания EPDE); UT2 / UWT2 — то же с `target_axes=0`; UI2 / UWI2 —
с `invariant_terms='refuse'`; V2 / VW2 — вращение по одной переменной (`spinvc_` + `spinvs_`). Сид 0; 20 эпох
(вращение, дрейф), 30 эпох (поля).

**Вращение** (финальный L0; «тождества» — доля членов L0, лишних по c² + s² = 1 и её производным):

| Рука | FULL (роботы) | Переменные: любой зачёт (строго) | Тождества на L0 | Лучший по WAPE член L0 = закон |
|---|---|---|---|---|
| U (10 ноября, сильная) | 4/6 | 8 (8)/12 | 90 % | 0/12 |
| U2 сильная | 4/6 | 8 (8)/12 | 91 % | 0/12 |
| UI2 сильная + правило | 5/6 | 10 (9)/12 | **0 %** | 2/12 |
| V2 сильная, по одной переменной | **6/6** | **12 (11)/12** | 83 %* | 0/12 |
| UW2 слабая | 1/6 | 2 (0)/12 | 97 % | 0/12 |
| UWI2 слабая + правило | **5/6** | **11 (7)/12** | **0 %** | 3/12 |
| VW2 слабая, по одной переменной | 5/6 | 10 (8)/12 | 67 %* | 0/12 |

\* Завышено: счётчик считает и члены, лишние только через производные второй компоненты, а в этих поисках вторая
компонента — значение без производных.

- U2 совпадает с U от 10 ноября: правки 10–12 ноября на вращение не повлияли.
- Самый трудный — робот #20 (медленный, нерегулярный). Его восстанавливает только V2, и то с WAPE ≈ 0.92.
- **Правило инвариантов.** По данным EPDE находит c² + s² − 1 = 0, дифференцирует по времени и строит базис Грёбнера
  (grevlex). Члены, делящиеся на старшие мономы, отказываются: s², s·s', s'², c·c'·s, c'²·s, …
- **После удаления тождеств** лучшие по WAPE места занимают:
  - «прокси скорости»: например, `ds/dt = c·c'² + c³`, что равно c·(ω²s² + c²) — это форма с мгновенной скоростью
    вращения;
  - в слабой форме с правилом — формы, полученные дифференцированием закона (`dc/dt = d²s/dt²`). Тест избыточности
    EPDE их бы отсеял, но он выключается, если в системе есть токены данных (здесь — контакты).

**Дрейф (7 систем):**
- U2 сильная: FULL 4 из 7 — #12 x/y и #27 x/y; закон появляется на первой эпохе. Так же, как 10 ноября.
- #18 (PWM20) и одиночный робот — ничего; у одиночного робота пропульсии нет, так и ожидалось.
- UW2 слабая: 0 из 7. Токены памяти в слабых строках становятся копиями цели (`dx/dt = m1_x + vb_x`, WAPE 0.005).
  Пространство поиска намеренно оставлено одинаковым в обеих формах.

**Поля** (сильная форма, 4 записи из 5 обсчитаны; слабая форма ещё считается):

| Поле | U2 (свободная цель) | UT2 (`target_axes=0`) |
|---|---|---|
| rho | 0/4 | **3/4** (перенос; дважды с релаксацией) |
| Px, Py | 2/4, 1/4 | 2/4, 1/4 |
| Wx, Wy | 4/4, 4/4 | 4/4, 3/3 (Wy на 4-й записи ещё считается) |

Фиксация оси времени меняет результат только для rho. У P и W закон по времени выигрывает и без неё.
На N40_PWM20_D40 rho не находится и с ней.

### 6.5 Почему слабая форма проигрывает на роботах (офлайн, кода нет)

- Слабая форма и центральные разности симметричны во времени. Члены релаксации на флуктуирующих данных
  исчезают: затухание Px −1.24 (прямая разность) → ≈ 0 (слабая); Wx −1.81 → 0. Связи через вращение остаются.
- Окно, выбранное по шуму, охватывает ≥ 1 оборот. Тогда формы вида g(поле) × производная цели — «низкочастотные
  копии цели» — бьют закон на каждом окне от 0.37 оборота: их невязка — производная ограниченной функции с
  гармониками ≥ 5, и тестовая функция её интегрирует. Шлюз половины мощности лечит окна, потерявшие сигнал, но не
  копии. Лечение должно быть в пространстве членов или в целевой функции (как правило инвариантов), а не в выборе
  окна.
- Вращение — исключение: оно детерминировано, и слабая форма на окне в 1 с поднимает R² закона у #20 с 0.19 до 0.68.

## 7. Плотность rho: почему закон переноса не находится

Работа второго сеанса, 12 ноября; запуски на `9bd360e`.

**Запуски EPDE.**

- `fieldv2_rho_N40_PWM10_D40`, свободная цель, 30 эпох:
  - первый фронт — 32 уравнения, все с целью d²rho/dx1² или d²rho/dx2², WAPE 0.43–0.63;
  - уравнений с целью по времени оценено 354 из 9108, в архив не попало ни одно;
  - закон переноса (WAPE 0.853, нестабильность 0.276) доминируется 10 членами фронта.
  Причина — **отбор, а не достижимость.** WAPE считается относительно своей цели, поэтому цели разного рода
  сравниваются по «доле объяснённого». Пространственная кривизна rho объясняет 43–57 % (WAPE 0.43–0.57),
приращение по времени — 8–24 % (WAPE 0.76–0.92).
- То же с `target_axes=0`:
  - фронт — 13 уравнений, все drho/dt, WAPE 0.77–0.92;
  - на нём перенос (0.853, 0.276) и перенос + релаксация (0.781, 0.453);
  - перенос найден на 57-й вставке нулевого поколения.
- `fieldv3_rho_N30_PWM10_D41` (токены Q, Push), `target_axes=0`:
  - все 14 уравнений фронта используют Q, ни одно — P;
  - `drho/dt = −1.115 Qx_x − 1.147 Qy_y` на (0.611, 0.089); лучший WAPE 0.571;
  - для сравнения, со старыми токенами на той же записи: лучший WAPE 0.689, перенос на (0.760, 0.381).
- То же **без** `target_axes`:
  - закона по времени на фронте нет: 27 уравнений, 20 из них — drho/dx1 через Pushx;
  - Q-закон не доминируется ни одним оценённым уравнением, но сам он ни разу не был оценён: 308 уравнений с целью
    по времени (3.1 %), лучшее — (0.656, 0.236).
  С хорошими токенами провал становится **проблемой достижимости**: семейство целей, все случайные члены которого
  доминируются, не закрепляется в популяции.
- `fieldv4_rho_N40_PWM10_D41` (дивергенции), `target_axes=0`:
  - все 24 уравнения фронта — drho/dt;
  - на фронте однотермовый `drho/dt = c·div_V` (0.663, 0.038); лучший WAPE 0.649.

**Офлайн-выводы второго сеанса (кода нет; подгонка на первой половине записи, WAPE — на второй).**

- Победившие пространственные соотношения — это статика:
  - `d²rho/dx1² = c·rho³·x²` — это купол среднего по времени профиля плотности; среднее по времени цели само даёт
    WAPE 0.591;
  - кривизна любого поля связана с самим полем через гауссово ядро сглаживания. Без подгонки предсказано
    a = 0.0195, измерено 0.018–0.021 для P и W.
- Не хватает **поля потока**. Поток J, построенный по трекам, даёт `drho/dt = −1.02 div J` с WAPE 0.13–0.17 —
  сохранение массы. Поляризация P — плохой заменитель потока: J ≈ 1.7–2.3·P, WAPE на отложенной половине 0.65–0.81.
  Сложные функции полей и бустинг не помогают (0.67–0.83).
- Длиннее шаг по времени — не лучше: 0.4 с близко к оптимуму. Прямое приращение — лучшая производная по времени
  для этих данных.
- Лучшие токены: дивергенция Q — WAPE 0.59–0.91 (у div P 0.75–0.93); предсказанная скорость V (учитывает соседей,
  которые давят на робота, и толчок самого робота в соседа) — 0.54–0.79; скорость с разрешёнными контактами —
  0.52–0.75.
- Ширина сглаживания 1.5 диаметра крышки даёт ещё −0.01..−0.04, но делает соотношения кривизны почти точными. Имеет
  смысл только вместе с `target_axes`.
- У одиночного робота курс не предсказывает его шаг (R² на отложенной части ≤ 0).

## 8. Как воспроизвести (текущая версия)

### 8.1 Код EPDE

Нужен коммит `9bd360e` ветки `domain_refactor`. Для рук с правилом инвариантов (UI2, UWI2) на него нужно наложить
патч `invariant_terms_on_9bd360e.patch`. Без патча ключ `invariant_terms` неизвестен.

Удобнее всего держать замороженные копии пакета `epde` и подавать их через `-Repo`. Тогда репозиторий может стоять
на любом коммите, а данные и обвязка берутся из него. В PowerShell 5.1 не передавайте `git archive` через `|` в
`tar`: конвейер портит двоичные данные. Пишите архив в файл:

```powershell
$repo = 'C:\path\to\EPDE'                       # клон с этой папкой и данными
New-Item -ItemType Directory -Force D:\epde_snap\9bd360e, D:\epde_snap\9bd360e_inv | Out-Null
git -C $repo archive -o D:\epde_snap\9bd360e.tar 9bd360e epde
tar -xf D:\epde_snap\9bd360e.tar -C D:\epde_snap\9bd360e
tar -xf D:\epde_snap\9bd360e.tar -C D:\epde_snap\9bd360e_inv
Set-Content D:\epde_snap\9bd360e\SNAPSHOT_HEAD '9bd360e'
Push-Location D:\epde_snap\9bd360e_inv
git apply "$repo\projects\robot\epde_u\invariant_terms_on_9bd360e.patch"
Set-Content SNAPSHOT_HEAD '9bd360e+invariant_terms'
Pop-Location
```

Можно и без копий: `git checkout 9bd360e`, при необходимости `git apply …patch`, и `-Repo` не указывать. Тогда
`epde` импортируется из самого клона.

Проверка патча: в клоне на `9bd360e` с наложенным патчем скопируйте `test_invariant_terms.py` (лежит здесь же) в
`tests/unit/` и запустите:

```powershell
python -m pytest tests/unit/test_invariant_terms.py -q      # 30 passed
```

### 8.5 Один прогон

Параметры `run_u.ps1`:
- `-Sys` — имя системы;
- `-Tag` — суффикс; чтобы работали скрипты анализа, задавайте `_<Рука>_e<Эпохи>`;
- `-Epochs`, `-Seed`;
- `-Form strong|weak`;
- `-Selected M` — до M членов кроме цели (дрейф: 8);
- `-TargetTime` — `target_axes=0`;
- `-Invariant` — `invariant_terms='refuse'`;
- `-Repo` — папка замороженной копии;
- `-Noise 0.05` — шум (только для батареи);
- `-Python` — путь к python; иначе берётся `$env:EPDE_PYTHON`, затем `python`;
- `-MinFree` — сколько ГБ свободной памяти ждать перед стартом.

```powershell
$e = 'C:\path\to\EPDE\projects\robot\epde_u'
$py = 'C:\path\to\envs\EPDE\python.exe'
# вращение, сильная форма (рука U2)
& "$e\run_u.ps1" -Sys spin_N30_PWM10_D41_12 -Tag _U2_e20 -Epochs 20 -Repo D:\epde_snap\9bd360e -Python $py
# то же с правилом инвариантов, слабая форма (рука UWI2)
& "$e\run_u.ps1" -Sys spin_N30_PWM10_D41_12 -Tag _UWI2_e20 -Epochs 20 -Form weak -Invariant -Repo D:\epde_snap\9bd360e_inv -Python $py
# вращение по одной переменной (рука V2 = системы spinvc_/spinvs_ с тегом U2)
& "$e\run_u.ps1" -Sys spinvc_N30_PWM10_D41_12 -Tag _U2_e20 -Epochs 20 -Repo D:\epde_snap\9bd360e -Python $py
# дрейф, до 8 членов
& "$e\run_u.ps1" -Sys driftx_N30_PWM10_D41_12 -Tag _U2_e20 -Epochs 20 -Selected 8 -Repo D:\epde_snap\9bd360e -Python $py
# поле rho с целью по времени (рука UT2)
& "$e\run_u.ps1" -Sys fieldv2_rho_N40_PWM10_D40 -Tag _UT2_e30 -Epochs 30 -TargetTime -Repo D:\epde_snap\9bd360e -Python $py
# поле rho с токенами Q/Push (раздел 7)
& "$e\run_u.ps1" -Sys fieldv3_rho_N30_PWM10_D41 -Tag _UT3_e30 -Epochs 30 -TargetTime -Repo D:\epde_snap\9bd360e -Python $py
# ячейка батареи: burgers, 5 % шума, сид 1, слабая форма
& "$e\run_u.ps1" -Sys burgers -Tag _U_n5_s1 -Epochs 50 -Seed 1 -Form weak -Noise 0.05 -Repo D:\epde_snap\9bd360e -Python $py
```

Выход — рядом со скриптами:
- `auto_<sys>_trace<Tag>.json` — уровни Парето с отметками зачёта и целевыми функциями;
- `_form.json` — версия EPDE, окна слабой формы;
- `.out` — печать первого фронта; для батареи в нём есть строгий итог `FULL on L0`;
- `_stream.tsv` и `_eqs.jsonl` — каждое оценённое уравнение.

Числа в разделе 4 получены на `48e3789`. На `9bd360e` у связанных систем (lv, lorenz, ns) другой поток
случайных чисел (исправление монетки), а шлюз окна сдвигает ~10 слотов. Поэтому отдельные ячейки могут отличаться
от таблицы раздела 4. Например, ns на чистых данных, сид 0: в батарее — точный закон, на исправленном коде (до
шлюза) — зачёт через уравнение Пуассона. Это в пределах разброса сидов батареи (точный / промах / Пуассон).

### 8.8 Ловушки

- `run_u.ps1` внутри PowerShell `Start-Job` зависает: python стоит на старте с 8 МБ памяти. Запускайте полосы
  обычными отдельными процессами.
- PowerShell 5.1 портит двоичные данные в конвейере: `git archive | tar` не работает, пишите архив в файл.
- В Windows Python пишет CRLF. Списки для bash сохраняйте с `newline='\n'`.
- Сравнивать прогоны можно только при равном дайджесте EPDE (`epde_digest` в `_form.json`). Пока идут запуски,
  не правьте дерево, из которого они импортируют `epde`, — для этого и нужны копии.
- Не вычисляйте один набор признаков из будущего шага другого: x и y в одной системе или приращения других полей
  дают утечку.
- `Factor.__init__` берёт число из глобального `np.random`. Любой построенный множитель (даже при перечислении
  библиотеки) сдвигает все дальнейшие случайные числа. Кэши по `id(obj)` без проверки идентичности тоже ломают
  воспроизводимость.

## 9. Открытые вопросы

- **Слабые поля** (UW2 / UWT2) и последние сильные прогоны на N40_PWM20_D41 ещё считаются. Таблица полей в 6.4
  неполная.
- **Тест избыточности выключен при токенах данных.** Из-за этого в слабой форме с правилом инвариантов на фронт
  проходят формы, полученные дифференцированием закона.
- **Прокси скорости вращения** (`c·c'² + c³` и т. п.) после удаления тождеств — истинные следствия данных или
  мусор? Решения пока нет.
- **Поиск без `target_axes` не закрепляет семейство целей по времени у rho** даже с хорошими токенами. Варианты:
  отдельные плоскости Парето для разных видов цели (не построено) или группировка фронта по цели в отчёте
  (не построено).
- **Неразрешённые ячейки батареи:** wave 5 % (u_tt тонет в шуме при любом окне-кандидате), pde_compound 5 %
  (окно), ns чистые (сид 1 — уравнения импульса не сгенерированы).
- **planned_duplicates='auto'** измерено на одном сиде; в коммиты не вошло.
